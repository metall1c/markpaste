# Deviations from the spec

Where the actual implementation differs from [TZ.md](../TZ.md) (the original specification, in Russian). Details are in the linked ADR.

| Spec item | What was done instead | Decision |
| --- | --- | --- |
| Sections 2, 9, 13: the reference is three Fedora 44 editions, the main difficulty is GNOME; the first stage is the core and Windows | The main platform is Fedora 44 KDE Plasma on Wayland, work starts with Linux | [0001](decisions/0001-linux-primary-kde-plasma.md) |
| Section 9: KDE Plasma 6.6 | Actually Plasma 6.7.5 (a Fedora 44 update) | [0001](decisions/0001-linux-primary-kde-plasma.md) |
| Section 8 "Threads": the libwayland-client connection is served in the main thread | A separate thread `markpaste-wayland` | [0002](decisions/0002-wayland-connection-thread.md) |
| Section 8: `IInputInjector` without session management; methods return `QFuture<void>` | Added `begin()`/`end()` (a RemoteDesktop session for the duration of a paste) and `isAvailable()`; the result is `QFuture<Status>`: declining a portal dialog is a normal outcome, not an exception | — (minor, described in `src/platform/Interfaces.h`) |
| EDT-3 + NFR-9: white text on the #FF5A1F accent with a contrast ≥ 4.5:1 | The badge background is darkened to 4.5:1, the frame keeps the original color | [0003](decisions/0003-badge-contrast.md) |
| ~~Section 7: logs via spdlog~~ | ~~For now `QLoggingCategory`; writing a file with rotation later, the spdlog decision is postponed~~ Replaced by the row on spdlog below (ADR 0014) | — |
| Section 10, mode 1: on Wayland the strip button only copies the set (mode 2) | On KDE and Sway (layer-shell) the button starts mode 1: the strip does not take keyboard focus from the chat. Without layer-shell, as in the spec | — (described in architecture/overview.md; awaiting a check) |
| Section 4, step 2: overlay on all monitors | The selection stays within one monitor; an area cannot be selected across a monitor border | — (a simplification for 1.0) |
| CAP-3: a ×4 magnifier | Present. In addition: a click without dragging selects the whole monitor, arrows move by 1 physical pixel, Shift+arrows change the size | — |
| Section 5.2 | In addition: a list of the shot's comments in the editor, a click on it opens the comment | — |
| STR-5: the strip can be collapsed to an icon and dragged to another edge | Moving to the left or right edge, at any height and on any monitor, on release, without smooth motion. Collapsing goes to the tray, not to an on-screen icon | [0004](decisions/0004-strip-placement-and-visibility.md) |
| Section 4, step 3: the strip appears after a capture; APP-1 | With an empty set the strip is hidden, the program is in the tray. The strip is shown after a capture and hides when the set becomes empty | [0004](decisions/0004-strip-placement-and-visibility.md) |
| Sections 2, 11, 14: the working name Pointshot, the ID `io.github.pointshot.Pointshot` | The name Markpaste, the ID `su._525.Markpaste`, the executable `markpaste`. TZ.md keeps the old name as is | [0005](decisions/0005-name-markpaste.md) |
| EDT-9: arrow and point marker, priority C | The arrow is done; in addition, freehand drawing. Both shapes are numbered marks with a comment in the shared numbering. ~~No point marker~~ (added later, ADR 0015) | [0006](decisions/0006-arrow-and-freehand-marks.md) |
| Section 10: one accent color for marks from settings | In addition: each mark has its own color, width and line style (solid, dashed, dotted), a panel in the editor. The accent from settings is the default color | [0007](decisions/0007-mark-pen.md) |
| Section 11: .deb and .rpm packages (CPack), repositories in OBS | .rpm, .deb and .tar.gz via CPack, built by hand for the release; no OBS and no signatures | [0008](decisions/0008-packaging-and-autostart.md) |
| Section 9: X11 capture via MIT-SHM | Capture via `QScreen::grabWindow` (Qt): 5 ms on Xvfb 1280×800; MIT-SHM if it turns out slow on 4K | [0011](decisions/0011-x11-hotkeys-and-xtest.md) |
| Section 5.2 | In addition: Esc in the editor. A fresh shot is discarded (removed from the set; with confirmation if it has marks, blur or a crop). A shot from the strip is only closed. Esc first closes the comment field, the crop and the selection | — |
| Section 7: logs via spdlog with rotation | Our own Qt logging handler (`qInstallMessageHandler`) with 1 MB × 3 rotation, no new dependency | [0014](decisions/0014-logs-and-update-check.md) |
| ~~NFR-4, APP-7: version check against GitHub Releases~~ | ~~The GitLab releases API~~: outdated since 2026-10-21, the check uses GitHub Releases again, as in the spec | [0014](decisions/0014-logs-and-update-check.md), [0024](decisions/0024-github-home-and-releases.md) |
| EDT-10: "text on image" | An option: a caption plate with the comment next to each badge; the message text does not change. There is no free "Text" tool | [0015](decisions/0015-point-marker-and-captions.md) |
| EDT-9: point marker | The number badge centered on the point and a ring of the mark color around it; key D | [0015](decisions/0015-point-marker-and-captions.md) |
| Section 11 "Hotkeys": capture, paste set, new shot, clear | In addition: "Capture without editor" (Ctrl+Print, `markpaste --capture-to-strip`), a shot straight to the strip. The ordinary capture (Print) is called "Capture with editor" in the UI. "Start a new set on the next capture" clears the set only after a paste or copy | [0022](decisions/0022-capture-to-strip.md) |
| Section 9: capture on Windows via Windows.Graphics.Capture, on Windows 10 via DXGI | DXGI Desktop Duplication on both systems (`DuplicateOutput1` with an 8-bit format, the system converts HDR), GDI as the fallback for a single monitor | [0016](decisions/0016-windows-platform.md) |
| Section 10: on UIPI the program switches to the "files + text" mode | The paste stops right away with the hint "the window runs as administrator, copy the set"; it does not switch to mode 2 by itself | [0016](decisions/0016-windows-platform.md) |
| Section 7: on Windows Qt 6.10+ from aqtinstall, the rest from vcpkg; section 12: building on a Windows image | For now, MinGW cross-compilation on Fedora (Qt 6.11.2 from the `mingw64-qt6-*` packages), tests under Wine. A CI build on Windows later | [0017](decisions/0017-windows-cross-build.md) |
| Section 11: Setup.exe (Velopack) with auto-update and a portable ZIP | A portable ZIP (35 MB) and an NSIS Setup.exe (23.8 MB): a per-user install without administrator rights, as in the spec, but without auto-update and without a signature. Velopack later | [0017](decisions/0017-windows-cross-build.md), [0023](decisions/0023-windows-installer-nsis.md) |
| Sections 3, 10: an empty comment gives a line with just the number, a shot without marks gives a header | A mark without a comment does not get into the text; if no shot has comments, there is no text at all (no headers, no numbers); if there are comments, a shot without them keeps its header | [0018](decisions/0018-marks-without-comment-in-text.md) |
| STR-2: the counter "3 shots · 4 comments" | The strip header shows the number of shots; the full counter is in its tooltip. "Clear" is a trash icon in the header | [0019](decisions/0019-ui-style.md) |
| Section 11 "Appearance": dark/light theme from the system | Background and text colors come from the system palette; the accent from settings also paints the selected tool, the primary button and shot letters; the buttons of the shot window and the strip are drawn by the program, not by the system style | [0019](decisions/0019-ui-style.md) |
| EDT-1: a rectangular mark; EDT-3: the badge at the frame's top-left corner | In addition: the frame shape is a rectangle, a rounded rectangle or an ellipse (a menu on the "Mark" tool). For the ellipse the badge is on the ellipse itself at the top-left, not in the corner of the bounding rectangle | [0020](decisions/0020-frame-shape.md) |
| Section 10: the mark frame with a 1 px white outline | A dark semi-transparent 1 px halo around mark lines; turned off with a checkbox on the "Appearance" tab (on by default). The white ring remains only on the number badge | [0021](decisions/0021-mark-halo.md) |
| STR-4: deleting a shot | In addition: a trash button on each strip thumbnail deletes the shot with one click, without confirmation (undone with Ctrl+Z in the editor) | [0019](decisions/0019-ui-style.md) |
