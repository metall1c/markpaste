# 0012. Сочетания клавиш на Wayland меняются только через систему

- Статус: принято (2026-10-20)

## Контекст

APP-3 (настройки), ТЗ разд. 9. Пользователь поменял в настройках сочетание вставки на Alt+V, а работало старое Ctrl+Alt+V. Через портал GlobalShortcuts программа только предлагает сочетание (`preferred_trigger`). KDE учитывает его при первой привязке, дальше хранит своё значение (`~/.config/kglobalshortcutsrc`) и новые предложения игнорирует (docs/problems.md, 2026-10-20).

## Решение

- `IHotkeys::systemAssignsTriggers()`: у портала — `true`, у X11 и заглушек — `false`.
- Если сочетания назначает система, в настройках поля «Захват» и «Вставить набор» только для чтения и показывают фактические сочетания от портала (`trigger_description`). Кнопка «Изменить сочетания…» вызывает `ConfigureShortcuts` (портал v2) — открывается диалог KDE для клавиш программы.
- Изменение в системе приходит сигналом портала `ShortcutsChanged` → `IHotkeys::triggerChanged` → контроллер обновляет фактические сочетания (мастер, подсказки) без перезапуска.
- Значения `hotkeys/capture` и `hotkeys/paste` в настройках программы остаются предложением для первой привязки; диалог настроек их не меняет.

## Рассмотренные варианты

- **Писать сочетание в KDE напрямую** через D-Bus `org.kde.kglobalaccel` или `kglobalshortcutsrc`. Отказ: только KDE, обходит портал и согласие пользователя, формат внутренний.
- **Пересоздавать привязку под новым id** (`paste-set-2`), чтобы портал принял новое предложение. Отказ: в настройках KDE копятся мёртвые записи, а KDE всё равно может спросить пользователя.
- **Оставить поле редактируемым с пояснением.** Так было — пользователь не понял, что значение не применится.

## Последствия

- На X11 (и Windows в будущем) поле по-прежнему редактируемое, сочетание применяется после перезапуска.
- На GNOME портал GlobalShortcuts v1 без `ConfigureShortcuts`: кнопки нет, поле только для чтения, менять — в настройках GNOME. Не проверено.
- `ShortcutsChanged` от KDE 6.7.5 на живой сессии пока не проверен.
