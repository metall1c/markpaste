# 0002. Своё подключение к Wayland для data-control — в отдельном потоке

- Статус: принято (2026-10-19)
- Требования ТЗ: PST-1, PST-8, разд. 7 («Протоколы … через отдельное подключение libwayland-client»), разд. 8 «Потоки»

## Контекст

ТЗ предлагает обслуживать подключение libwayland-client для data-control через `QSocketNotifier` в главном потоке. На прототипе это привело к взаимной блокировке.

Когда наша же программа вставляет из буфера, которым владеет наш data-control-источник (пользователь нажал Ctrl+V в поле комментария, пока набор лежит в буфере), происходит следующее:

1. Qt в главном потоке читает буфер **блокирующе**: QtWaylandClient ждёт данные из pipe.
2. Композитор присылает запрос `send` нашему data-control-источнику, то есть на наше второе подключение.
3. События этого подключения разбирает тот же главный поток, а он заблокирован. Ответа нет, Qt ждёт до своего таймаута, и вставка приходит пустой.
4. Попутно ломается клиентский автоповтор клавиш в Qt (на Wayland его делает клиент): пока главный поток стоит, срабатывает таймер повтора, и один Ctrl+V превращается в десятки вставок.

Симптом на самопроверке: картинки «дошли» (Qt не читал данные, проверял только форматы), а текст пришёл пустым 37 раз.

## Решение

`WaylandConnection` и все слушатели протоколов (`DataControlDevice`) живут в отдельном потоке `pointshot-wayland` со своим циклом событий. `DataControlClipboard` — потокобезопасный фасад для главного потока: методы передаются в поток Wayland через `QMetaObject::invokeMethod`, результаты возвращаются через `QFuture`. Данные в pipe пишет пул `QtConcurrent`, чтобы поток Wayland оставался свободным.

## Рассмотренные варианты

- **Главный поток, как в ТЗ.** Отпадает из-за блокировки выше.
- **Запретить вставку в свои окна, пока буфер наш.** Хрупко: нельзя перехватить все пути чтения буфера внутри Qt (контекстное меню, средняя кнопка, перетаскивание).
- **Ставить буфер через QClipboard (подключение Qt).** На Wayland Qt меняет буфер только с фокусом клавиатуры, а нам нужна запись из фона.

## Последствия

- Код в `platform/linux/wayland/` обязан соблюдать правило: обращаться к объектам протокола только из потока подключения.
- `hasGlobal()` и `global()` читают снимок, сделанный при подключении, поэтому безопасны из любого потока.
- Проверка — `pointshot-pastetest --self-test --in-process`: приёмник в нашем процессе получает все картинки и текст.
